# 文件读写

## 让数据留下来

程序里的变量都活在内存中——程序一关，全部蒸发。想让数据长期保存（用户记录、配置、统计结果），就要写到**文件**里。Python 读写文件，只需要一个 `open()` 函数。

## 写文件与读文件

```python
# 写：模式 "w" 是 write
with open("diary.txt", "w", encoding="utf-8") as f:
    f.write("第一天：学了变量\n")
    f.write("第二天：学了循环\n")

# 读：模式 "r" 是 read
with open("diary.txt", "r", encoding="utf-8") as f:
    content = f.read()
    print(content)
```

逐个拆解：

- `open("文件名", "模式")` 打开文件，返回一个文件对象，这里起名叫 `f`；
- `with` 语句会在代码块结束时**自动关闭文件**——这是标准写法，不用担心忘记关闭；
- `encoding="utf-8"` 指定编码，**要写中文务必加上**，否则 Windows 上容易出现乱码；
- `\n` 是换行符（第十二章的转义字符），一行写一条，方便以后逐行读。

**打开模式速查**：

| 模式 | 含义 | 注意 |
| --- | --- | --- |
| `r` | 读 | 文件不存在会报 `FileNotFoundError` |
| `w` | 写（清空重写） | **会清空文件原有内容！** |
| `a` | 追加 | 在文件末尾续写，不清空 |

> **常见事故**：想给文件“补充”几行，却用了 `"w"` 模式——旧内容被全部清空。往已有文件续写，用 `"a"` 模式。

### 为什么总要写 encoding="utf-8"

不写 `encoding` 时，Python 会用**操作系统的默认编码**去读写文件。这个默认值并不统一：

| 系统 | 常见的默认编码 |
| --- | --- |
| Windows（中文环境） | GBK |
| macOS / Linux | UTF-8 |

后果是：**同一段代码换台电脑就可能读出乱码，甚至直接抛 `UnicodeDecodeError`**。它还属于最难排查的那一类问题——文件看起来像“坏了”，实际只是写和读用了不同的编码。

所以请养成一条纪律：**只要写 `open()`，就顺手写上 `encoding="utf-8"`**。

```python
with open("diary.txt", "w", encoding="utf-8") as f:
    f.write("第一天：学了变量\n")
```

多打这几下不花什么成本，却能让文件在任何电脑上读出来都是原样。

想亲眼看它出问题，可以运行本章的配套示例脚本：那段“默认编码”演示会先用 `utf-8` 写一份中文文件，再故意用系统默认编码读回来，把真实结果打印给你看——在 Windows 中文环境下，它常常就是一句 `UnicodeDecodeError`。

## 逐行读取

文件很大时，`f.read()` 一次读完可能吃力，更常用逐行遍历——循环又来了：

```python
with open("diary.txt", "r", encoding="utf-8") as f:
    for line in f:
        print(line, end="")     # line 自带换行符，end="" 避免双重换行
```

回忆第九章：`print` 的 `end` 参数默认是换行 `\n`，这里改成空字符串。

## 和异常处理配合

文件可能不存在——被用户删了，或者名字写错了。上一章学的 `try / except` 立刻派上用场：

```python
try:
    with open("notes.txt", "r", encoding="utf-8") as f:
        print(f.read())
except FileNotFoundError:
    print("文件不存在，先创建它吧")
```

## 动手：成绩存档

把成绩写进文件，再读出来统计——一条完整的“存储—读取—计算”链路：

```python
scores = [90, 85, 77, 100, 66]

with open("scores.txt", "w", encoding="utf-8") as f:
    for s in scores:
        f.write(str(s) + "\n")          # 文件里只能放文本，先转字符串

with open("scores.txt", "r", encoding="utf-8") as f:
    total = 0
    count = 0
    for line in f:
        total += int(line.strip())      # 去掉换行符再转回整数
        count += 1

print(f"共 {count} 条成绩，总分 {total}，平均分 {total / count:.1f}")
```

输出：`共 5 条成绩，总分 418，平均分 83.6`。写入时 `str()` 转成文本（第十二章），读出时 `strip()` 去换行、`int()` 转回数字（第五、十二章）——写、读、算一气呵成。

### 选学：更省心的路径写法

本章一直用字符串表示文件名：`open("diary.txt", ...)`。文件一多、目录一深，靠字符串拼路径很容易出错。Python 自带了专门管路径的模块 `pathlib`：

```python
from pathlib import Path

p = Path("data") / "diary.txt"     # 用 / 拼路径，比手写字符串清楚
print(p)                            # data\diary.txt（Windows；macOS/Linux 上是 data/diary.txt）

print(p.exists())                   # False —— 文件在不在，一句话就能问
print(p.name)                       # diary.txt —— 只要文件名
print(p.suffix)                     # .txt —— 只要扩展名
```

`p.exists()` 能在打开文件**之前**先问一句“你在不在”，很多场合比 `try / except` 更顺手。本章的记账本作业用 `try / except` 完全够用，等你开始处理多层目录时再回来用它。

### 选学：文件到底被写到哪儿了

这是新手最容易困惑的一个坑：`open("diary.txt", "w")` 里的 `"diary.txt"` 是**相对路径**，它相对于你**运行程序时所在的目录**——而不是 `.py` 文件所在的目录。于是“代码和文件明明在同一个文件夹里”，运行却报 `FileNotFoundError`。

想知道相对路径是从哪儿算起的，用 `pathlib` 问一句当前目录：

```python
from pathlib import Path

print(Path.cwd())     # 当前工作目录，所有相对路径都从这里算起
```

两个实用结论：

- 在 VS Code 里按 F5 运行，当前目录通常是**你打开的那个项目文件夹**；而在命令行里 `cd` 到别处再运行同一个脚本，文件就会写到那个“别处”去；
- 找不到自己刚写的文件时，先 `print(Path.cwd())`，再顺着这个目录去找。

如果希望文件**一定**待在脚本旁边，可以用 `Path(__file__).parent` 拿到脚本自己的目录（第十四章认识过 `__name__`，`__file__` 是同族的自动变量）：

```python
from pathlib import Path

here = Path(__file__).parent        # 本脚本所在目录，与从哪儿运行无关
target = here / "diary.txt"

with open(target, "w", encoding="utf-8") as f:
    f.write("这次一定写在脚本旁边\n")
```

在 VS Code 里点“运行”时，当前目录到底是项目根还是脚本目录，各版本行为可能不同——与其猜，不如用 `Path.cwd()` 看一眼真实的值。这正好呼应上一章那句话：**不要靠猜，去看真实的值。**

## 本章挑战作业

**简易记账本**。做一个“每次运行都记得上一次”的支出记录程序——这是文件最典型的用途，**没有参考答案**：

功能要求：

1. 程序启动时，读取 `ledger.txt`：显示已有的每一笔支出和**历史总额**；文件不存在就当作 0 笔账，正常开始（不许崩）；
2. 循环询问用户输入一笔支出（数字）或 `q` 退出；
3. 每输入一笔，立刻以**追加模式**写入文件，一行一笔；
4. 输入 `q` 退出前，显示本次新增的笔数和本次总额。

要求：

- 读文件必须配合 `try / except`（回忆上一章的 `FileNotFoundError`）；
- 写入用 `"a"` 模式——想想为什么用 `"w"` 是灾难（回忆本章的模式表）；
- 读取时逐行处理：先 `strip()` 再转数字，回忆本章“成绩存档”的处理链路。

> **提示**：历史总额需要“读文件时累加”——准备一个 `total` 变量，循环累加（第八章的套路）。本次新增笔数是另一个独立计数器。两种计数器谁在循环外初始化、谁每轮归零，想清楚这一点，程序就对了。

**自测标准**：运行程序记三笔账退出，再运行一次——历史账目和总额都在，而且新账接着旧账记，没有被清空。

## 本章小结

- `open()` + `with` 读写文件，代码块结束自动关闭。
- 三种模式：`r` 读、`w` 写（会清空！）、`a` 追加；写中文加 `encoding="utf-8"`。
- 不写 `encoding` 就用系统默认编码（Windows 中文环境常见是 GBK），换台电脑就可能乱码——所以每次都顺手写上 `utf-8`。
- `f.read()` 整体读，`for line in f` 逐行读；`f.write()` 只能写字符串。
- 文件不存在会报 `FileNotFoundError`，用 `try / except` 接住。
- 相对路径相对于**运行程序时的当前目录**，不是脚本所在目录；用 `Path.cwd()` 确认，用 `Path(__file__).parent` 锚定脚本目录。
