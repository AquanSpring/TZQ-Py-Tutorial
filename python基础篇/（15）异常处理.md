# 异常处理

## 意外总会发生

这本教程一直在教你看报错：`TypeError`、`IndentationError`、`KeyError`……报错的正式名字叫**异常（Exception）**。默认情况下，异常一旦发生，程序立刻终止。

但用户是不可控的：你让他输数字，他偏输 `"abc"`。好的程序要能**接住意外**，给用户一条退路，而不是自己崩溃——这就是**异常处理**。

## try / except：尝试与兜底

```python
try:
    age = int(input("请输入年龄："))      # 这行可能报错
    print(f"明年你就 {age + 1} 岁")
except ValueError:
    print("输入的不是数字，请重试！")       # 报错时执行这里

print("程序继续运行")                      # 两种情况都会走到这里
```

结构规则：

- **try 里放“可能出错的代码”，except 里放“出错后的对策”**；
- try 块中一旦发生异常，剩下的代码不再执行，直接跳到对应的 except；
- 没有异常发生，except 就被跳过；
- 无论哪种情况，程序都不会崩溃，继续往下运行。

`except` 后面写的是**异常类型**，只接住指定的类型。`ValueError` 是“值不合适”——`"abc"` 转不成 `int` 就是它。

## 一个 try 可以接多种异常

```python
try:
    a = int(input("被除数："))
    b = int(input("除数："))
    print(f"结果为 {a / b}")
except ValueError:
    print("请输入数字")
except ZeroDivisionError:
    print("除数不能为 0")
```

输入 `10` 和 `0`，会得到“除数不能为 0”，程序稳如泰山。

### 还有 else、finally 和 assert

**`else`**：挂在 `except` 后面，**只有没出错时才执行**。它和“把代码直接写在 try 里”的区别是：try 里的代码一旦出错，剩下的就都不执行了；而 else 里的代码，出错时压根不会进去。

```python
try:
    age = int("18")
except ValueError:
    print("输入的不是数字")
else:
    print("转换成功，年龄是", age)   # 只有没出错才走到这里
```

**`finally`**：不管有没有出错都会执行的收尾代码。它最常见的搭档是文件——无论中途成功还是失败，都要有个收尾动作：

```python
try:
    f = open("不存在的文件.txt", "r", encoding="utf-8")   # 这里一定失败
    print(f.read())
except FileNotFoundError:
    print("文件不存在")
finally:
    print("无论成功还是失败，这句都会执行")
```

> **提示**：下一章会学到 `with open(...)`，它把“自动关闭文件”做成了语法，所以实际写文件时 `finally` 用得比这里少——但“无论如何都要收尾”这个想法很重要。

**`assert`（断言）**：给“我认为这里一定是这样”加一道自动检查，条件不成立就直接报 `AssertionError`：

```python
age = 18
assert age >= 18, "年龄必须满 18"    # 不成立就报错，并带上这句说明
print("断言通过")
```

它适合写在**调试和自测**里（比如验证自己的函数返回值对不对），不适合用来处理用户输入错误——用户乱输要用 `try / except`，那才是本章前面讲的正事。

### 选学：主动抛出异常（raise）

前面都是“异常发生了，我去接住”。反过来，你也可以**主动抛出**异常：当调用者给的参数根本不合理时，与其让它悄悄算出个错结果，不如当场喊停。

```python
def set_age(age):
    if age < 0 or age > 150:
        raise ValueError("年龄必须在 0 到 150 之间，收到的是 " + str(age))
    return age

print(set_age(18))       # 18

try:
    set_age(-5)
except ValueError as e:
    print("ValueError:", e)
```

`raise` 后面跟一个异常对象。好处是：错误在**发生的地方**就被明确指出，而不是拖到很远的地方，才暴露成一个看不懂的结果。

三者的分工可以这样记：

| 手段 | 用在哪 | 出问题说明什么 |
| --- | --- | --- |
| `assert` | 调试、自测 | **你自己的代码**写错了 |
| `raise` | 正式逻辑 | **调用你的人**用错了 |
| `try / except` | 正式逻辑 | 外部世界（用户输入、文件）不可控 |

想在项目里定义自己的异常类型，只要继承 `Exception` 就行（继承的概念第十七章会讲）：`class MyError(Exception): pass`。进阶篇再展开。

## 常见异常速查表

前面各章见过的报错，在这里全部对上号：

| 异常 | 触发场景 | 首次出现在 |
| --- | --- | --- |
| `SyntaxError` | 语法写错（如少冒号） | 第四章 |
| `IndentationError` | 缩进不一致 | 第四章 |
| `NameError` | 使用了未定义的变量 | 第十三章 |
| `TypeError` | 类型不匹配（如 `"5" + 5`） | 第五、六章 |
| `ValueError` | 类型对但值不合适（如 `int("abc")`） | 本章 |
| `IndexError` | 列表索引越界 | 第十章 |
| `KeyError` | 字典键不存在 | 第十一章 |
| `ZeroDivisionError` | 除数为 0 | 本章 |
| `FileNotFoundError` | 文件不存在 | 下一章 |

看报错的第一步永远是：**找到最后一行——异常类型 + 说明文字**，这一章让它从“读”升级为“接住”。

## 动手：给 BMI 计算器加保护

第九章的 BMI 计算器，用户乱输就会崩。加上异常处理：

```python
try:
    height = float(input("请输入身高（米）："))
    weight = float(input("请输入体重（千克）："))
    bmi = weight / height ** 2
    print(f"你的 BMI 是 {bmi:.2f}")
except ValueError:
    print("请输入合法的数字！")
except ZeroDivisionError:
    print("身高不能为 0！")
```

分别输入 `abc` 和 `1.6 / 0` 的情况试一试——程序不再崩溃，而是给出友好提示。

## 选学：从“读报错”到“调试”

到这里你已经会读报错了。但如果程序**不报错、只是结果不对**呢？这时需要**调试（Debug）**——主动去观察程序运行中每一步的真实情况。

**第一步：缩小范围。** 在可疑的位置插一句 `print()`，把中间变量的值打出来，看它是不是你以为的那个值。这是最朴素也最有效的手段，写十年代码也还在用：

```python
total = 0
for s in scores:
    total += s
    print(f"加上 {s} 后，total = {total}")     # 每一步都摊开看
```

**第二步：用断点。** 在 VS Code 里，直接点行号左边的空白处，会出现一个红点——这就是**断点（Breakpoint）**。按 `F5` 启动调试，程序会跑到这一行**停下来**，这时你可以：

- 在左侧的“变量（VARIABLES）”面板里看到**当前所有变量**的值；
- 按 `F10`（单步跳过）一行一行往下走，每走一步都看变量怎么变；
- 按 `F5`（继续）直接跑到下一个断点。

> **调试的核心只有一句话：不要靠猜，去看真实的值。** 程序的行为和你以为的不一样，永远是某个变量的值和你以为的不一样——断点就是让你亲眼看到它的工具。这一招配合本章的异常处理，程序再出问题你也不至于束手无策。

## 本章挑战作业

**造一个“永不崩溃”的输入函数**。真实软件里“请你输入一个数字”的对话，背后都有一个反复要求重试的机制。现在把它封装成函数，**没有参考答案**：

任务一：写函数 `ask_int(prompt)`：

1. 显示 `prompt` 提示语，读取用户输入并尝试转成整数；
2. 转换失败就提示“请输入一个整数”，然后**再次**要求输入——直到成功为止；
3. 成功后把这个整数**返回**给调用处。

任务二：用这个函数写一个除法程序：先后询问被除数和除数，输出商。要求除数为 0 时不崩溃，单独提示“除数不能为 0”。

要求：

- 任务二的除数为 0 属于另一种异常（回忆本章速查表），要在调用处单独接住；
- 主程序里不许出现裸的 `int(input(...))`——所有整数输入都必须走你的 `ask_int`。

> **提示**：`while True + try/except + return` 三件套：try 里转换成功就 `return`（回忆第十三章：return 会立刻结束函数，正好也跳出了循环）；转换失败会跳到 except，提示后循环自动进行下一轮。想通“return 能同时结束函数和循环”这一层，这道题就通了。

**自测标准**：输入 `abc`、`1.5`、空回车都不会崩，程序坚持要到一个整数为止；除数输 0 时得到友好提示而不是红色报错。

## 本章小结

- 异常发生时程序默认终止；`try / except` 可以接住异常，让程序继续运行。
- try 放可能出错的代码，except 按异常类型写对策；一个 try 可以接多种异常。
- `ValueError` 是“值不合适”，与 `TypeError`（类型不匹配）不同。
- 遇到新异常，先读最后一行的类型和说明，再决定是改代码还是加处理。
- 程序不报错但结果不对时，用 `print` 缩小范围，或用断点 + `F10` 单步观察真实的值。
